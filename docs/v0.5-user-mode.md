# DiyorOS v0.5: User mode, syscall'lar va dasturlar

Bu bosqichda DiyorOS'da **haqiqiy jarayonlar** paydo bo'ldi. Endi dasturlar alohida fayl (ELF) sifatida `/bin` papkasida turadi va har biri:
- protsessorning cheklangan rejimida (**ring 3**) ishlaydi;
- o'zining **alohida xotirasiga** ega (har birining o'z Page Directory'si bor);
- kernel bilan faqat **syscall'lar** (`int 0x80`) orqali gaplashadi;
- xatoga yo'l qo'ysa, **faqat o'zi o'ladi**. Kernel va boshqa dasturlar ishlashda davom etadi.

Bu bosqich DiyorOS'ni o'quv kernelidan Linux tamoyillari asosida ishlaydigan tizimga aylantirdi.

**Yangi fayllar:**
- Kernel: `src/kernel/process.c` (ELF yuklovchi), `src/kernel/syscall.c`, `include/elf.h`, `include/process.h`, `include/syscall_nums.h`, `include/irq.h`.
- Dasturlar: `user/` papkasi (`crt0.s`, `libc.c`, 6 ta dastur, `initrd.s`, `linker.ld`).

**O'zgargan fayllar:** `gdt.c` (TSS), `paging.c` (alohida xotiralar), `task.c`, `idt.c`, `keyboard.c` (Ctrl+C), `Makefile`.

---

## 1. Ring 0 va ring 3: protsessor himoyasi

x86 protsessorda 4 ta ruxsat darajasi bor, biz ulardan ikkitasini ishlatamiz:

| | Ring 0 (kernel) | Ring 3 (dastur) |
|---|---|---|
| Barcha xotira | ✅ | ❌ faqat `PAGE_USER` belgili sahifalar |
| `cli`, `hlt`, `lgdt`, `mov cr3` | ✅ | ❌ General Protection Fault |
| Portlar (`in`, `out`) | ✅ | ❌ General Protection Fault |
| Ekran xotirasi (0xB8000) | ✅ | ❌ Page Fault |

Joriy daraja `CS` registrining pastki 2 bitida saqlanadi: kernel uchun `0x08` (ring 0), dastur uchun `0x1B` (ring 3). GDT'dagi 3- va 4-segmentlar (v0.1'dan beri bor edi) endi ishlatila boshlandi.

### TSS: nima uchun kerak?

Dastur ishlayotgan paytda uzilish kelsa (masalan, taymer), protsessor ring 0'ga o'tadi. Lekin uzilishga ishlov berish uchun **dasturning stekidan foydalanib bo'lmaydi**, chunki dastur uni ataylab buzgan bo'lishi mumkin. Shuning uchun protsessor **TSS**'dan (Task State Segment) kernel stekining manzilini (`esp0`) oladi va o'sha stekka o'tadi.

Har bir jarayonning o'z kernel steki bor (8 KB). Scheduler har safar jarayon almashtirganda `esp0` ni yangilaydi.

## 2. Har bir jarayonning o'z xotirasi

```
           Jarayon A (PID 2)                Jarayon B (PID 3)
0xFFFFFFFF ┌──────────────────┐            ┌──────────────────┐
           │ kernel heap      │ ─┐      ┌─ │ kernel heap      │   bir xil
0xD0000000 │ (PAGE_USER yo'q) │  ├──────┤  │ (PAGE_USER yo'q) │   Page Table'lar
0xC0000000 ├──────────────────┤  │      │  ├──────────────────┤
           │ stek (64 KB)     │  │      │  │ stek (64 KB)     │
           │       ...        │  │      │  │       ...        │   HAR XIL
           │ heap (sbrk)      │  │      │  │ heap (sbrk)      │   fizik frame'lar
0x40000000 │ kod + ma'lumot   │  │      │  │ kod + ma'lumot   │
           ├──────────────────┤  │      │  ├──────────────────┤
           │ kernel (identity)│ ─┘      └─ │ kernel (identity)│   bir xil
0x00000000 └──────────────────┘            └──────────────────┘
```

- **Kernel qismi** barcha jarayonlarda bir xil, chunki Page Directory yozuvlari nusxalanadi. Lekin unda `PAGE_USER` belgisi yo'q, shuning uchun dastur unga tegsa, darhol Page Fault bo'ladi.
- **User qismi** (`0x40000000` – `0xC0000000`) har jarayonda o'ziniki.
- Jarayon almashganda `CR3` registriga uning Page Directory'si yoziladi va butun virtual xotira "almashadi".
- **Isbot:** `isolate &` ni ikki marta ishga tushir. Ikkalasi ham `counter` o'zgaruvchisini `0x40001008` manzilida ko'radi, lekin qiymatlari har xil bo'ladi (2000… va 3000…).
- Muhim nozik joy: kernel heap uchun Page Table'lar **oldindan** yaratiladi (`paging_init`). Aks holda keyin yaratilgan Page Table'larni eski jarayonlar ko'rmay qolardi.
- Jarayon tugaganda uning barcha frame'lari, Page Table'lari va Page Directory'si PMM'ga qaytariladi. `mem` buyrug'i ko'rsatadiki, o'nlab dastur ishlab tugagandan keyin ham band frame'lar soni o'zgarmaydi, ya'ni xotira sizib chiqmaydi.

## 3. Syscall: dastur kernelga qanday murojaat qiladi

```
  dastur (ring 3)                            kernel (ring 0)
  ───────────────                            ───────────────
  printf("Salom")
    └─ write(1, "Salom", 5)
         EAX=1  EBX=1  ECX=buf  EDX=5
         int 0x80  ─────────────────────►  IDT[0x80] (DPL=3!) -> isr128
                                           syscall_handler:
                                             - buf dasturnikimi? tekshiruv
                                             - ekranga 5 belgi
                                             - EAX = 5
         ◄──────────────────────────────── iret (ring 3 ga qaytish)
    EAX = 5
```

- IDT'dagi `0x80` yozuvi **DPL = 3**: dastur faqat shu uzilishni chaqira oladi. Boshqa uzilishni chaqirsa (masalan, `int 0x81`), General Protection Fault bo'ladi.
- **Ko'rsatkichlarni tekshirish eng muhim xavfsizlik qoidasi.** Dastur `write(1, 0x00100000, 16)` deb kernel xotirasini ekranga chiqarishga urinishi mumkin. `user_ok()` funksiyasi manzil dastur hududida ekanini va sahifalar mavjudligini tekshiradi. Aks holda `EFAULT` (-14) qaytariladi (`hack 7` buni ko'rsatadi).
- Fayl deskriptorlari ham himoyalangan: har bir fd'ni qaysi jarayon ochgani saqlanadi, boshqa jarayon uni ishlata olmaydi.

| № | Syscall | Vazifasi |
|---|---|---|
| 0 | `exit(kod)` | Dasturni tugatish |
| 1 | `write(fd, buf, n)` | 1/2 — ekranga, 3+ — faylga |
| 2 | `read(fd, buf, n)` | 0 — klaviaturadan qator, 3+ — fayldan |
| 3 | `open(yo'l, flaglar)` | Faylni ochish |
| 4 | `close(fd)` | Faylni yopish |
| 5 | `sleep(ms)` | Uxlash |
| 6 | `getpid()` | O'z PID'ini bilish |
| 7 | `uptime()` | Ishlash vaqti (ms) |
| 8 | `yield()` | Navbatni boshqaga berish |
| 9 | `sbrk(n)` | Heap'ni kattalashtirish (`malloc` shundan foydalanadi) |
| 10 | `sysinfo(&s)` | Tizim haqida ma'lumot |
| 11 | `setcolor(c)` | Matn rangi |
| 12 | `clear()` | Ekranni tozalash |

## 4. ELF yuklovchi (`process.c`)

`hello` deb yozilganda nima bo'ladi:

1. Shell bu ichki buyruq emasligini ko'radi va `/bin/hello` faylini qidiradi.
2. `process_spawn()` faylni VFS orqali xotiraga o'qiydi.
3. ELF sarlavhasi tekshiriladi: sehrli raqam `\x7FELF`, 32-bit, x86, bajariladigan fayl. Mos kelmasa, "bajariladigan fayl emas" xatosi chiqadi.
4. **Yangi Page Directory** yaratiladi.
5. Har bir `PT_LOAD` segment uchun frame'lar ajratiladi va fayldagi baytlar nusxalanadi.
   - **Kod segmenti faqat o'qish uchun ochiladi.** Dastur o'z kodini o'zgartira olmaydi (`hack 4`).
   - Segment manzili dastur hududidan tashqarida bo'lsa (masalan, kernelga yozmoqchi bo'lsa), fayl rad etiladi.
6. 64 KB stek ajratiladi, unga `argc` va `argv` yoziladi. Shu sababli `hello Diyorbek` buyrug'ida dastur argumentni ko'radi.
7. Ring 3 vazifa yaratiladi. Kernel stekida "soxta uzilish kadri" quriladi (`CS = 0x1B`, `SS = 0x23`, `ESP` = dastur steki), va `iret` protsessorni ring 3'ga o'tkazadi.

**Dasturlar kernelga qanday tushadi?** Disk hali yo'q (u v0.6'da bo'ladi). Shuning uchun `make` dasturlarni yig'adi va `user/initrd.s` ularni `.incbin` bilan kernel ichiga joylaydi. Yuklanishda ular `/bin` ga oddiy fayl sifatida yoziladi. Shundan keyin ular boshqa fayllardan farq qilmaydi: `cp /bin/hello /tmp/salom` qilib, `/tmp/salom` ni ham ishga tushirsa bo'ladi.

## 5. Xatolarni ushlash: kernel panic va Segmentation fault

`idt.c` da exception kelganda `CS` ning ruxsat darajasi tekshiriladi:

```c
if ((r->cs & 3) == 3)        // xato dasturda
    process_fault(r, ...);   // -> "Segmentation fault", faqat shu jarayon o'ladi
kernel_panic(r);             // xato kernelning o'zida -> tizim to'xtaydi
```

Ikkalasini solishtirib ko'rsat:
- `hack 1` — dastur NULL'dan o'qiydi. Ekranda qizil xabar chiqadi, shell ishlashda davom etadi.
- `crash` — kernelning o'zi 0 ga bo'ladi. Natijada qizil kernel panic ekrani chiqadi va tizim to'xtaydi.

## 6. Kichik libc va dasturlar (`user/`)

- **`crt0.s`** — dasturning birinchi kodi. U stekdan `argc` va `argv` ni olib, `main()` ni chaqiradi, keyin `exit()` ni.
- **`libc.c`** — `printf`, `puts`, `readline`, `malloc`/`free`, `strlen`, `atoi`, `rand` va syscall o'ramlari. Linux'dagi glibc'ning juda kichik o'xshashi.

| Dastur | Nimani ko'rsatadi |
|---|---|
| `hello [ism]` | argc/argv, PID, kod va stek manzillari, `malloc`, `sysinfo` |
| `guess` | Klaviaturadan kiritish (`read`). Son topish o'yini |
| `primes [N]` | Protsessorni ko'p ishlatadi. `primes 5000000 &` bilan fonda ishlatib, `ps` bilan kuzat |
| `hack [1-8]` | **Himoya sinovlari.** 8 xil usulda kernelni buzishga urinadi |
| `isolate` | **Xotira izolyatsiyasi.** Ikki nusxasini `&` bilan ishga tushir |
| `kundalik` | Fayl syscall'lari: `open`, `write`, `read`, `close` |

### Shell'dagi yangiliklar

- **Dasturni nomi bilan ishga tushirish.** `hello` deb yozish kifoya, `/bin/hello` avtomatik topiladi.
- **`dastur &`** dasturni fonda ishga tushiradi. U tugaganda `[PID 5] primes tugadi (kod 0)` xabari chiqadi.
- **Ctrl+C** oldingi plandagi dasturni to'xtatadi. Agar dastur ishlamayotgan bo'lsa, kiritilayotgan qatorni bekor qiladi.
- **`ps`** da yangi ustunlar bor: `T` (K — kernel oqimi, U — user dastur) va `XOTIRA`.
- **`help`** endi `/bin` dagi dasturlarni ham ko'rsatadi.

## Ustozga ko'rsatish ketma-ketligi

1. `ls /bin`, keyin `hello Diyorbek`: dastur ring 3'da ishlaydi, kodi `0x40000000` manzilida.
2. `hack 1`, `hack 2`, `hack 5`: har safar faqat dastur o'ladi.
3. `hack 7`: kernel noto'g'ri manzilni rad etadi va dastur ishlashda davom etadi.
4. `isolate &` va yana `isolate &`: manzil bir xil, qiymatlar har xil.
5. `primes 20000000 &`, keyin `ps`: U turidagi jarayon 100% CPU oladi, shell esa javob beraveradi. So'ng `kill <PID>`.
6. `primes 50000000`, keyin **Ctrl+C**.
7. `guess`: o'yin.
8. `mem`: xotira sizib chiqmaganini ko'rsatish.
9. Oxirida `crash`: kernel xatosi bilan farqini ko'rsatish.

## Himoyada beriladigan savollar

1. **User mode va kernel mode farqi?**
   Ring 3'da imtiyozli buyruqlar (`cli`, `hlt`, `out`) va kernel xotirasi taqiqlangan. Ring 0'da hammasi ruxsat etilgan. Daraja `CS` registrining pastki 2 bitida saqlanadi.

2. **Nega dasturlarni ring 3'da ishlatamiz?**
   Himoya uchun: bitta dasturning xatosi yoki zararli kodi kernelni va boshqa dasturlarni buza olmaydi.

3. **Syscall nima va qanday ishlaydi?**
   Dasturning kerneldan xizmat so'rash usuli. Bizda bu `int 0x80`: raqam EAX'ga, argumentlar EBX/ECX/EDX'ga yoziladi, natija EAX'da qaytadi. Zamonaviy tizimlarda bu ish tezroq `sysenter`/`syscall` buyruqlari bilan bajariladi.

4. **Nega kernel dastur bergan ko'rsatkichni tekshirishi shart?**
   Aks holda dastur kernelni o'zi uchun kernel xotirasini o'qishga yoki yozishga majbur qila oladi. Bunday zaifliklar real OS'larda ham topilgan.

5. **TSS nima uchun kerak?**
   Ring 3'dan ring 0'ga o'tishda protsessor qaysi stekka o'tishini TSS'dagi `esp0` dan biladi. Dastur steki ishonchsiz bo'lgani uchun undan foydalanilmaydi.

6. **Jarayonlar xotirasi qanday ajratiladi?**
   Har jarayonning o'z Page Directory'si bor. Bir xil virtual manzil har xil fizik frame'larga tushadi (`isolate` demosi). Kernel qismi esa umumiy, lekin `PAGE_USER` belgisisiz.

7. **ELF fayl nima?**
   Bajariladigan fayl formati. Unda sarlavha, segmentlar ro'yxati (qaysi baytni qaysi manzilga yuklash kerakligi) va kirish nuqtasi (entry) saqlanadi.

8. **`.bss` qanday yuklanadi?**
   ELF'da u `memsz > filesz` ko'rinishida beriladi. Ortiqcha qism nol bilan to'ldiriladi, chunki biz frame'larni ajratganda ularni tozalaymiz.

9. **Segmentation fault nima?**
   Dastur ruxsat etilmagan xotiraga murojaat qilganda keladigan xato. Protsessor Page Fault yoki GPF beradi, OS esa shu dasturni to'xtatadi.

10. **Dastur tugaganda xotirasi qanday qaytariladi?**
    `paging_free_directory` barcha user frame'larni, Page Table'larni va Page Directory'ni PMM'ga qaytaradi. Kernel steki `kfree` qilinadi, ochiq fayllari yopiladi (`vfs_close_owner`).

11. **Nega jarayon o'z xotirasini o'zi bo'shata olmaydi?**
    Chunki u shu xotirada (va o'z kernel stekida) ishlab turibdi. U ZOMBIE holatiga o'tadi, xotirasini esa keyinroq shell bo'shatadi.

12. **Ctrl+C qanday ishlaydi?**
    Klaviatura uzilishi Ctrl+C ni aniqlaydi va oldingi plandagi jarayonni ZOMBIE qiladi. Scheduler unga boshqa vaqt bermaydi, shell esa uyg'onadi. Unix'da bu SIGINT signali deb ataladi.

13. **`malloc` dasturda qanday ishlaydi?**
    U `sbrk` syscall orqali kerneldan yangi sahifalar so'raydi. Kernel ularni dasturning heap hududiga ulaydi, so'ng `malloc` ularni kichik bloklarga bo'lib beradi.

14. **Qanday cheklovlar qoldi?**
    Dasturlar kernel ichida keladi, chunki disk yo'q (v0.6). `fork`/`exec` va pipe yo'q (v0.8). Kernel ichidagi sinxronizatsiya hozircha uzilishlarni o'chirish orqali qilinadi, mutex v0.8'da qo'shiladi.
