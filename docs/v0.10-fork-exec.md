# v0.10 — Unix jarayon modeli: fork, copy-on-write, exec, deskriptor jadvallari

v0.8 gacha DiyorOS'da yangi dastur faqat bitta yo'l bilan ishga tushardi: `spawn()` — kernel
faylni o'qib, yangi jarayon yaratadi (Windows'dagi `CreateProcess` kabi). Unix'da esa bu ikki
qadam:

```
pid = fork();              // 1. joriy jarayonning NUSXASI
if (pid == 0) {            //    bolada fork() 0 qaytaradi
    dup2(fd, 1);           //    (ixtiyoriy) stdout ni faylga yoki kanalga ulash
    exec("/bin/wc", "");   // 2. bola o'zini boshqa dasturga aylantiradi
}
wait(pid, &kod);           // ota bola tugashini kutadi
```

Bu bosqichda DiyorOS'ga shu model to'liq qo'shildi:

| Nima | Qayerda | Mohiyati |
|---|---|---|
| `fork()` | `task.c: task_fork` | jarayon nusxasi: registrlar, xotira, deskriptorlar, papka |
| Copy-on-write | `paging.c`, `pmm.c` | fork xotirani nusxalamaydi; sahifa faqat yozilganda ko'chiriladi |
| `exec()` | `process.c: process_exec`, `task.c: task_exec` | jarayon xotirasini yangi dastur bilan almashtirish |
| Deskriptor jadvali | `task_t.fd`, `vfs.c` | har jarayonniki o'zi; `dup`, `dup2` |
| Joriy papka | `task_t.cwd`, `vfs.c` | har jarayonniki o'zi; `chdir`, `getcwd` |
| `wait(0)` | `task.c: task_wait_child` | istalgan bolani kutish |
| `qobiq` | `user/qobiq.c` | **user rejimidagi shell**: pipe, `<`, `>`, `>>`, `cd` — fork + exec bilan |
| `nusxa` | `user/nusxa.c` | fork, CoW va exec namoyishi (o'lchovlar bilan) |
| `hack 9` | `user/hack.c` | "fork bomb" — kernel chegaralari sinovi |
| `fds`, `/proc/fds` | `vfs.c: vfs_fd_report` | deskriptor jadvallarini ko'rsatish |

6 ta yangi syscall: `fork` (20), `exec` (21), `dup` (22), `dup2` (23), `chdir` (24), `getcwd` (25).

Yangi kod: ~1 200 qator (jami ~20 000, shrift faylisiz). 34 ta fayl o'zgardi yoki qo'shildi.

## 2. fork() — jarayonning nusxasi

### Ikkita qaytish

`fork()` bir marta chaqiriladi, lekin **ikki marta qaytadi**: otada va bolada. Bu qanday
bo'ladi?

Dastur `int 0x80` qilganda protsessor va `isr_common` barcha registrlarni jarayonning kernel
stekiga saqlaydi (`registers_t` kadri). Syscall tugagach, registrlar shu kadrdan tiklanadi va
`iret` dasturni `int 0x80` dan keyingi buyruqqa qaytaradi.

`task_fork` bola uchun yangi kernel stek ajratadi va unga **otaning kadrini aynan ko'chiradi**,
faqat bitta farq bilan: `EAX = 0`. Bola birinchi marta ishga tushganda scheduler shu kadrni
tiklaydi — bola ham `int 0x80` dan keyingi buyruqdan davom etadi, go'yo u ham `fork()` ni
chaqirgan. Otaga esa odatdagidek natija qaytadi: bolaning PID i.

```
ota:   ... int 0x80 (EAX=20) ---> kernel: task_fork ---> EAX = 7 (bola PID) ---> pid = 7
bola:                              kadr nusxasi, EAX=0 ---> scheduler ---> iret -> pid = 0
```

### Nimalar nusxalanadi

| Narsa | fork'da | Izoh |
|---|---|---|
| Registrlar | nusxa (EAX = 0) | bola aynan o'sha joydan davom etadi |
| Xotira | **copy-on-write** | 3-bo'lim |
| FPU holati | nusxa | `fnsave` + `frstor` (fnsave FPU ni tozalaydi — darhol qaytaramiz) |
| Deskriptorlar | havola +1 | ochiq fayl va kanallar umumiy (offset ham) — 5-bo'lim |
| Joriy papka | nusxa | |
| PID | yangi | ota — `parent_pid` |
| Jarayon guruhi | o'sha | Ctrl+C otani ham, bolani ham to'xtatadi |
| `heap` (brk) | o'sha | |

### Chegaralar

- Bitta jarayonda bir vaqtda ko'pi bilan **4 ta bola** (`TASK_MAX_CHILDREN`), tizimda **16 ta
  vazifa** (`MAX_TASKS`). Yetmasa — `fork()` manfiy son qaytaradi.
- `hack 9` — **fork bomb**: har bir jarayon to'xtovsiz fork qiladi. Natija:
  ```
  Kernel to'xtatdi: fork() = -22. Tizimda 16 ta vazifa (maksimum 16),
  har bir jarayonda ko'pi bilan 4 bola. Kernel va shell ishlayapti.
  ^C
  [13 ta jarayon Ctrl+C bilan to'xtatildi]
  ```
  Hamma bolalar otaning guruhida (`pgid`) — Ctrl+C butun guruhni bir zarbada to'xtatadi.

## 3. Copy-on-write (CoW)

### Muammo

Oddiy fork barcha sahifalarni nusxalashi kerak edi: 1 MB lik dastur — 256 ta frame va 1 MB
`memcpy`. Ko'pincha bola darhol `exec()` qiladi va bu nusxa bekorga ketadi.

### Yechim: yozilgandagina nusxalash

1. **fork paytida** (`paging_fork_directory`): bolaga yangi Page Directory va yangi **Page
   Table lar** yaratiladi, lekin ulardagi yozuvlar **otaning frame lariga** ishora qiladi.
   Yoziladigan har bir sahifa **ikkala tomonda ham** faqat o'qish qilinadi (`PAGE_RW` olib
   tashlanadi) va `PAGE_COW` belgisi qo'yiladi. Har bir frame hisoblagichi +1.
2. **Kimdir yozmoqchi bo'lsa**: sahifa faqat o'qish uchun — protsessor **Page Fault** (#14)
   beradi. Xato kodi: bit 0 = 1 (sahifa bor), bit 1 = 1 (yozish). `paging_cow_fault`:
   - frame ni boshqa hech kim ishlatmasa (hisoblagich = 1) — sahifani shunchaki yozishga
     ochadi (nusxa kerak emas);
   - aks holda — yangi frame ajratadi, 4 KB ni nusxalaydi, yozuvni yangi frame ga o'tkazadi,
     eski frame hisoblagichi −1.
3. Uzilishdan qaytgach **o'sha buyruq qaytadan bajariladi** — endi muvaffaqiyatli. Dastur
   hech narsani sezmaydi.

```
fork dan oldin:     ota: 0x40003000 -> frame A (RW)

fork dan keyin:     ota:  0x40003000 -> frame A (faqat o'qish, COW)    A.refs = 2
                    bola: 0x40003000 -> frame A (faqat o'qish, COW)

bola yozdi:         ota:  0x40003000 -> frame A (faqat o'qish, COW)    A.refs = 1
                    bola: 0x40003000 -> frame B (RW)  <- A ning nusxasi

ota yozdi:          ota:  0x40003000 -> frame A (RW)  <- nusxasiz, oxirgi egasi
```

### PAGE_COW belgisi qayerda?

Page Table yozuvining 9–11 bitlari (AVL) protsessor uchun ahamiyatsiz — ular OS ga berilgan.
Biz 9-bitni (`0x200`) ishlatamiz: "bu sahifa aslida yoziladigan, faqat vaqtincha yopilgan".
Haqiqiy faqat o'qiladigan sahifa (dastur kodi) bu belgini olmaydi — unga yozish avvalgidek
"Segmentation fault".

### Frame hisoblagichi (`pmm.c`)

Bitta fizik frame endi bir nechta jarayonda bo'lishi mumkin, demak "kim bo'shatadi?" degan
savol tug'iladi. Javob: **oxirgisi**. Har frame uchun bitta bayt hisoblagich (1 GB = 262 144
frame = 256 KB):

| Funksiya | Hisoblagich |
|---|---|
| `pmm_alloc_frame` | 1 |
| `pmm_frame_ref` (fork) | +1 |
| `pmm_free_frame` | −1; 0 bo'lsa — frame bo'sh |
| `pmm_free_frame_zero` | −1; 0 bo'lsa — nol bilan tozalab bo'shatadi (bo'linmas) |

### Kernel ham user xotirasiga yozadi

`read(fd, buf, n)` da `buf` ga **kernel** yozadi. Agar `buf` CoW sahifada bo'lsa, kernelning
o'zi Page Fault oladi (`CR0.WP` yoqilgan — kernel ham faqat o'qiladigan sahifaga yoza olmaydi).
Shuning uchun `user_ok(..., write)` endi avval `paging_make_writable` ni chaqiradi: oraliqdagi
CoW sahifalar nusxasi oldindan olinadi. Ehtiyot chorasi sifatida Page Fault ishlovchisi kernel
rejimidagi CoW xatosini ham hal qiladi.

### Topilgan xato: `sbrk` va umumiy sahifa

`sbrk` heap'ni qayta kattalashtirganda xaritada qolgan sahifani **fizik manzil orqali** nol bilan
tozalardi. fork'dan keyin bu frame aka-ukasi bilan umumiy bo'lishi mumkin — ikkalasining xotirasi
tozalanib ketardi. Endi avval o'z nusxasi olinadi (`paging_make_writable`).

### TLB

fork otaning sahifa yozuvlarini o'zgartiradi (RW → faqat o'qish). Protsessor eski yozuvlarni
TLB (manzillar keshi) da saqlab qolgan bo'lishi mumkin — shunda ota CoW ni chetlab o'tib, umumiy
frame ga yozib yuborardi. Shuning uchun fork oxirida TLB tozalanadi (`CR3` qayta yoziladi).

### Natija (nusxa, 1 MB massiv)

| Holat | Bo'sh xotira o'zgarishi |
|---|---|
| fork'dan keyin | **−16 KB** (Page Directory, 2 ta Page Table, stek sahifalari) |
| bola 256 sahifaga yozdi | **−1024 KB** (har sahifaning nusxasi) |
| bola tugadi | hammasi qaytdi (bo'sh xotira fork'dan oldingi bilan bir xil) |

fork 1 MB lik jarayon uchun 0 ms (taymer aniqligi 10 ms) davom etadi.

## 4. exec() — dasturni almashtirish

`exec(yo'l, argumentlar)`:

1. Yangi dastur **to'liq** yuklanadi: fayl o'qiladi, yangi Page Directory, ELF segmentlari,
   stek va `argc/argv` (`load_image` — `spawn` bilan umumiy kod).
2. Faqat shundan keyin: `CR3` yangi xotiraga o'tadi, **eski xotira bo'shatiladi** (CoW
   bo'lsa — faqat hisoblagich −1), eski dasturning oynalari yopiladi, FPU holati tashlanadi.
3. Syscall kadri o'zgartiriladi: `EIP` = yangi dasturning kirish nuqtasi, `ESP` = yangi stek.
   Syscall dan "qaytish" yangi dasturning boshiga olib boradi.

Tartib muhim: agar 1-qadamda xato bo'lsa (fayl yo'q, ELF buzilgan, xotira yetmadi), `exec()`
xato kodi bilan **qaytadi** va jarayon eski dasturda davom etadi (`nusxa` 3-qismi buni ko'rsatadi).
Muvaffaqiyatli `exec()` hech qachon qaytmaydi.

**Saqlanadi:** PID, ota, jarayon guruhi, deskriptorlar, joriy papka.
**Almashadi:** xotira, nom, heap, FPU, oynalar.

## 5. Deskriptorlar: uch qatlam

### Avval (v0.8)

Bitta umumiy jadval: `fds[32]`, har yozuvda `owner` (PID). Dastur raqamni (masalan, 5) to'g'ridan-
to'g'ri ishlatardi, kernel esa har safar "bu sizniki mi?" deb tekshirardi. stdin/stdout esa
alohida maydonlar (`fd_in`, `fd_out`) edi.

### Endi (Unix dagidek)

```
jarayon A (qobiq):   fd: [0]=konsol [1]=konsol [2]=konsol [3]=#7 [4]=#8
jarayon B (wc):      fd: [0]=#7     [1]=konsol [2]=konsol
                                \            
                                 v           
umumiy jadval:         files[7] = { pipe, o'qish uchi, refs = 2 }
                       files[8] = { pipe, yozish uchi, refs = 1 }
                                 |
                                 v
                              pipe (4 KB bufer)
```

1. **Jarayon jadvali** (`task_t.fd[16]`): fd raqami → umumiy jadvaldagi yozuv raqami.
   Maxsus qiymatlar: `FD_FREE` (−1) — bo'sh, `FD_CONSOLE` (−2) — klaviatura/ekran.
2. **Ochiq fayl yozuvi** (`vfs_file_t files[64]`): fayl tuguni yoki pipe, **pozitsiya
   (offset)**, rejim, **havolalar soni** (`refs`).
3. **Fayl tuguni** (`vfs_node_t`) yoki pipe.

Natijalari:

- **Izolyatsiya tuzilmaning o'zida**: jarayon faqat o'z jadvalidagi raqamlarni nomlay oladi.
  Boshqa jarayonning fayliga yetib borishning yo'li yo'q — `owner` tekshiruvi kerak emas.
- **fork va dup yozuvni nusxalamaydi**, unga havola qo'shadi (`refs + 1`). Pozitsiya umumiy:
  ota va bola bitta faylga ("dastur > log") navbatma-navbat yozsa, bir-birining ustidan
  yozmaydi. v0.8 da buning uchun "oxiriga qo'shish" rejimiga majburan o'tkazilardi — endi bu
  hiyla kerak emas.
- **Yozuv oxirgi havola yopilganda bo'shaydi**. Kanalda bu muhim: yozish uchini **hamma**
  yopmaguncha o'quvchi EOF ko'rmaydi. Shuning uchun `qobiq` fork'dan keyin ota tomonidagi
  kanal uchlarini darhol yopadi.
- **Eng kichik bo'sh raqam** (Unix qoidasi): `close(1); open("f")` → yangi fd = 1.
- stdin/stdout/stderr endi alohida mexanizm emas — shunchaki fd 0, 1, 2.

### Jadvallarni ko'rish: `fds` va `/proc/fds`

`fds` (kernel shell) yoki `/proc/fds` (istalgan dastur o'qiy oladi) uch qatlamni ko'rsatadi.
`qobiq` ichida `head 40 < /proc/fds`:

```
Jarayonlar jadvallari (fd -> #ochiq fayl, kon - klaviatura/ekran):
  1 shell      0:kon 1:kon 2:kon
  2 qobiq      0:kon 1:kon 2:kon
  4 head       0:#0 1:kon 2:kon          <- head ning stdin i fayl: qobiq "<" ni dup2 bilan ulagan
Umumiy jadval (1 / 64 band):
  #  HAVOLA  OFFSET  NIMA
  0      1       0  /proc/fds
```

`head 40 /proc/fds | grep #` da esa bir lahzalik holat ko'rinadi: `head` ning fd 1 i kanalga
ulangan, ikkinchi bola esa hali **exec qilmagan** — u hamon "qobiq" nomida va kanalning o'qish
uchini fd 3 da ushlab turibdi (birozdan keyin `dup2(3, 0)`, `close(3)`, `exec("/bin/grep")`).

### dup va dup2

```
dup(fd)        — fd ning nusxasi eng kichik bo'sh raqamga
dup2(fd, to)   — "to" ni yopib, unga fd ning nusxasini qo'yish
```

`qobiq` da `sanoq 5 > /disk/a.txt` shunday bajariladi:

```
pid = fork();
// bolada:
fd = open("/disk/a.txt", O_WRITE|O_CREATE|O_TRUNC);   // fd = 3
dup2(fd, 1);                                          // fd 1 endi fayl
close(fd);                                            // 3 kerak emas
exec("/bin/sanoq", "5");                              // sanoq printf qiladi -> faylga
```

`sanoq` yo'naltirilganini bilmaydi ham: u shunchaki fd 1 ga yozadi.

### Kernel kodi o'zgarmadi

Kernel ichidagi shell, oyna menejeri, `edit`, `paint` — ular ham vazifa, ularning ham jadvali
bor. `vfs_open` / `vfs_read` / `vfs_close` avvalgidek int raqam bilan ishlaydi, faqat endi bu
raqam **joriy vazifaning** jadvalida. Kernel shell kanal qurganda bolaga o'z deskriptorini
beradi (bola nusxa oladi), keyin o'zinikini yopadi — xuddi Unix shell kabi.

## 6. Joriy papka har jarayonniki

Avval `cwd` VFS da bitta global o'zgaruvchi edi: dastur `chdir` qilsa, shell ham "ko'chib"
qolardi. Endi `task_t.cwd`:

- yangi jarayon yaratganining papkasini oladi (`spawn`, `fork`), `exec` saqlaydi;
- `chdir` faqat joriy jarayonniki o'zgartiradi;
- papkani o'chirish (`rm`) va diskni uzish (`umount`) **barcha** tirik jarayonlarning papkasini
  tekshiradi: biror jarayon `/disk` ichida turgan bo'lsa — `band`.
- `shutdown` diskni uzishdan oldin hamma jarayonlarni `/` ga o'tkazadi.

## 7. qobiq — user rejimidagi shell

`user/qobiq.c` (~280 qator) — oddiy dastur, kernelning ichki funksiyalariga tegolmaydi.
Hamma narsa syscall orqali:

| Vazifa | Syscall lar |
|---|---|
| Dastur ishga tushirish | `fork`, `exec`, `wait` |
| Kanal `a \| b` | `pipe`, `fork` ×2, `dup2(p[1], 1)` / `dup2(p[0], 0)`, `close` |
| `> fayl`, `>> fayl`, `< fayl` | `open`, `dup2`, `close` |
| `cd`, `pwd`, taklif satri | `chdir`, `getcwd` |
| Skript rejimi | `isatty(0)`: stdin kanal bo'lsa — taklif chiqmaydi, buyruqlar undan o'qiladi |

Kanal uchun kod sxemasi (`run` funksiyasi):

```
prev = -1
har bir bosqich i:
    oxirgisi bo'lmasa: pipe(p)
    pid = fork()
    bolada: prev -> fd 0, p[1] -> fd 1, p[0] ni yopish, exec(...)
    otada:  prev ni yopish, p[1] ni yopish, prev = p[0]
hamma bolalarni wait()
```

Kernel shell (`src/shell/shell.c`) bilan solishtirish — himoyada yaxshi savol:

| | Kernel shell | qobiq |
|---|---|---|
| Rejim | ring 0, kernel oqimi | ring 3, oddiy dastur |
| Dastur ishga tushirish | `process_spawn_ex` (bitta qadam) | `fork` + `exec` |
| Ichki buyruqlar | 60+ (kernel ma'lumotlariga to'g'ridan-to'g'ri kiradi) | 4 (`cd`, `pwd`, `exit`, `yordam`) |
| Xato | butun tizimga ta'sir qilishi mumkin | faqat o'zi o'ladi |

## 9. Himoya savollari

**fork() qanday qilib ikki marta qaytadi?**
Bolaning kernel stekiga otaning syscall paytidagi registrlar kadri ko'chiriladi, faqat
`EAX = 0`. Scheduler bolani birinchi marta ishga tushirganda shu kadrni tiklaydi va `iret` uni
`int 0x80` dan keyingi buyruqqa olib boradi. Otada esa syscall odatdagidek bolaning PID i bilan
tugaydi.

**Copy-on-write nima va u nima uchun kerak?**
fork'da sahifalar nusxalanmaydi: ota va bola bir xil frame larni oladi, ikkalasida ham sahifa
"faqat o'qish" qilinadi. Kimdir yozganda Page Fault keladi va kernel faqat O'SHA sahifaning
nusxasini oladi. fork tez bo'ladi va xotira faqat o'zgargan sahifalar uchun sarflanadi; fork
dan keyin darhol exec qilinsa, deyarli hech narsa nusxalanmaydi.

**Kernel CoW Page Fault ni oddiy xatodan qanday ajratadi?**
Uch shart: xato kodida "sahifa bor" va "yozish" bitlari yoqilgan; manzil user hududida;
sahifa yozuvida bizning `PAGE_COW` belgimiz (AVL bit 9) bor. Uchalasi bo'lmasa — haqiqiy xato
(masalan, dastur o'z kodiga yozmoqchi), jarayon to'xtatiladi.

**Nima uchun frame hisoblagichi kerak?**
CoW'dan keyin bitta frame bir nechta jarayonda. Jarayon tugaganda frame ni darhol bo'shatsak,
qolgan jarayon bo'shatilgan (boshqaga berilgan) xotirani ishlatib qolardi. Hisoblagich 0 ga
tushgandagina frame bo'sh. Yana bir foyda: oxirgi egasi yozganda nusxa olmasdan sahifani
shunchaki ochish mumkin.

**fork'dan keyin nima uchun TLB tozalanadi?**
fork otaning sahifa yozuvlarini "yozish mumkin" dan "faqat o'qish" ga o'zgartiradi. Protsessor
eski tarjimani TLB'da saqlab qolgan bo'lsa, u Page Fault bermay umumiy frame ga yozardi va bola
o'zgarishni "ko'rib" qolardi.

**exec xato bo'lsa nima bo'ladi?**
Yangi dastur alohida xotirada to'liq yuklanadi va faqat muvaffaqiyatdan keyin eskisi o'chiriladi.
Xato bo'lsa, yangi xotira bo'shatiladi va `exec()` xato kodi bilan qaytadi — jarayon eski
dasturda davom etadi.

**exec'dan keyin ochiq fayllar nima bo'ladi?**
Saqlanadi — shu sababli shell fork va exec orasida `dup2` bilan stdin/stdout ni ulay oladi.
(Linux'da `O_CLOEXEC` bayrog'i bilan ochilganlari yopiladi; bizda bunday bayroq yo'q.)

**Nega fork va exec alohida, bitta "spawn" emas?**
Orada bolaning muhitini sozlash mumkin: deskriptorlarni qayta ulash, papkani o'zgartirish,
cheklovlar qo'yish — bularning hammasi oddiy syscall lar bilan, spawn'ga har bir imkoniyat uchun
yangi parametr qo'shmasdan. Kamchiligi: katta jarayonni fork qilish qimmat bo'lishi mumkin (CoW
buni kamaytiradi). Shuning uchun POSIX'da `posix_spawn` ham bor, DiyorOS'da ham ikkalasi:
`spawn` (v0.8) va `fork` + `exec` (v0.10).

**Deskriptor jadvali nima uchun ikki qatlamli?**
Jarayon jadvali — "mening 3-faylim qaysi?" Umumiy yozuv — pozitsiya va rejim. fork va dup
qilingan deskriptorlar bitta pozitsiyani bo'lishishi kerak (ota va bola bitta log faylga
navbatma-navbat yozadi) — shuning uchun pozitsiya jarayon jadvalida emas, umumiy yozuvda.

**Kanalda EOF qachon keladi va nima uchun qobiq kanal uchlarini yopadi?**
EOF — kanalning yozish uchiga havolalar soni 0 ga tushganda. fork'dan keyin ota ham yozish
uchini ushlab turadi. Ota uni yopmasa, `wc` yozuvchi tugaganini hech qachon bilmaydi va abadiy
kutadi.

**`cd` nima uchun dastur emas, shellning ichki buyrug'i?**
`cd` alohida dastur bo'lsa, fork qilingan BOLANING papkasi o'zgarardi va bola tugashi bilan bu
o'zgarish yo'qolardi. Papka jarayonga tegishli — shuning uchun uni shellning o'zi o'zgartiradi.
(`exit` ham shunday.)

**Fork bomb'dan himoya qanday?**
Ikki chegara: bitta jarayonda ko'pi bilan 4 ta bola va tizimda 16 ta vazifa. Ular tugagach
`fork()` xato qaytaradi. Kernel va shell ishlayveradi, hamma bolalar bitta guruhda — Ctrl+C
hammasini to'xtatadi. (Linux'da: `ulimit -u`, cgroups `pids.max`.)

**Zombi jarayon nima?**
Tugagan, lekin otasi hali `wait()` qilmagan jarayon: xotirasi va fayllari bo'shatilgan, jadvalda
faqat chiqish kodi saqlanadi. `wait()` kodni olib, yozuvni tozalaydi. Ota o'lgan bo'lsa,
zombini kernel o'zi tozalaydi (Linux'da `init` "asrab oladi").

## 10. Qanday tekshirildi

v0.9 dagi to'rt konfiguratsiyada (`pc` multiboot, `q35` AHCI, ISO + BIOS, ISO + UEFI) avvalgi
40 ta buyruqli to'plam va v0.10 ning 25 ta yangi buyrug'i:

- `nusxa` ikki marta, har biridan keyin `mem` — frame lar soni bir xil (xotira oqmaydi).
- `qobiq`: `pwd`, `cd`, kanal (2 va 3 bosqich), `>`, `>>`, `<`, mavjud bo'lmagan dastur
  (`[kod 127]`), `exit 3`, ichida `pi` (FPU: fork + exec dan keyin ham to'g'ri) va `ota`
  (spawn + pipe user shell ichida).
- `hack 9` + Ctrl+C: jadval to'ladi, keyin hammasi tozalandi.
- Diskka yozilgan fayl Linux'da `mcopy` + `seq` bilan bayt-ma-bayt solishtirildi, `fsck.fat`
  xatosiz.

## 11. Cheklovlar

- Signal ishlov beruvchilari yo'q: Ctrl+C `qobiq` ning o'zini ham to'xtatadi (Unix shell
  bolalarini alohida guruhga qo'yadi va o'zi SIGINT ni e'tiborsiz qoldiradi).
- `exec` argumentlarni bitta satr sifatida oladi (`argv` massivi emas) — `spawn` bilan bir xil.
- `O_CLOEXEC`, `setpgid`, `waitpid` bayroqlari (WNOHANG) yo'q.
- `qobiq` da fon rejimi (`&`), qo'shtirnoq va o'zgaruvchilar yo'q.
- Stek o'smaydi (64 KB), heap qisqarganda sahifalar qaytarilmaydi.
